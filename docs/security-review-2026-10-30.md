# 2026-10-30 安全与功能复查

检查基线：`9d33c59908e5e41c5030fa613e52ad9d61887746`，目标站点 https://boang.fun 。本报告记录代码复查、隔离复现、修复及测试；实际生产提交、备份位置和部署后网络验收以交付目录的部署记录为准。

## 结论与范围

确认并修复四处问题，另补充 HTTPS 强制策略和音视频握手限流。本次没有发现无需登录即可读取后台配置、导出用户数据或读取私有图片的路径。检查范围包括认证、账号隔离、管理员权限、附件访问与容量、自习室成员撤权、OAuth、AI 出站限制、依赖、部署权限和常用功能回归。这是有边界的复查，不是“没有任何漏洞”的保证，也未进行压力攻击、真实用户数据修改或付费 AI 调用。

## 已复现并修复的问题

| 问题 | 风险判断及前提 | 修复与证据 |
|---|---|---|
| 多标签页切换账号后，续期返回 B 的凭证，旧页面仍保留 A 的身份 | 高优先级隐私问题；需要在同一浏览器切换账号，可能把 A 的本地数据用 B 的凭证同步 | 接受凭证前核对返回的用户 ID；不一致时清除旧页面凭证并停止旧请求。页面内续期合并，跨标签页通过浏览器 Web Locks 排队。回归覆盖错账号响应、并发续期、退出途中的旧响应；真实浏览器两标签页同时六次续期全部成功，峰值并发为一。离线库仍按账号保留。 |
| 退出登录后，旧 access JWT 及轮换前凭证仍可使用 | 中风险；需已取得有效访问凭证，原先最多继续使用两个小时 | 每次登录使用稳定会话 ID，轮换保留该 ID；退出持久化吊销该会话的全部凭证，其他设备的独立登录不受影响。API 和音视频均校验。旧格式 refresh Cookie 自动升级，不强制全部用户重新输密码。 |
| 反复上传、删除可释放逻辑配额，磁盘文件却继续积累 | 中风险可用性问题；需已登录账号，可能耗尽服务器磁盘 | 只有物理删除成功才释放配额；显式删除立即清理，旧头像及失败删除由维护任务重试；分配配额时锁定事务；本地写入预留 512 MiB，失败清除部分文件。小配额重复上传/删除和写入失败均有回归。 |
| 被踢出、封禁或退出登录后，静默音视频连接撤权延迟 | 中风险隐私问题；需原先已被允许加入音视频房 | 每五秒复核会话、账号和成员权限，失效即关闭信令并通知其他成员移除连接；原实现仅在收消息时复核，静默连接需等到六十秒超时。三种撤权情形均有回归。P2P 架构依赖正常客户端关闭媒体，无法追回已被合法接收的内容。 |

会话吊销使用现有持久化状态表，没有新增数据库迁移。附件清理只处理已标记删除的对象；正常头像、错题和相册不参与清理。

## 额外加固与已检查边界

- 容器 Nginx 仅在 HTTPS 来源下发送一年 HSTS；音视频升级握手按可信来源 IP 限流。宿主机 Nginx 和已有 Let's Encrypt TLS 配置不改动。
- 未登录读取认证资料、后台概览/配置/导出、同步、附件、自习室和小组的九个实际接口，均返回 401；伪造访问凭证也被拒绝。
- `.env`、`.git/config`、`server/.env`、`backup.zip` 返回前端 SPA 页面，未返回对应文件内容。HTTP 200 本身不能当作敏感文件泄露证据。
- 外站 Origin 无 CORS 授权，外站预检被拒绝。refresh Cookie 为 Secure/HttpOnly/SameSite=Lax；私有图片经登录和对象权限检查，接口响应禁止公共缓存。
- 公网 API 端口未直接发布，Web 容器仅绑定宿主机回环地址；容器使用只读根文件系统。配置文件为 root 所有、权限 600，私钥与密钥不进入仓库、前端或交付报告。
- 复查 Markdown/公式渲染、同步账号边界、图片路径与解码、GitHub 已验证邮箱绑定、OAuth state/PKCE、AI 出站地址限制、管理员授权、备份恢复及 TURN 鉴权；相关回归通过。
- npm 官方注册表审计报告零项已知漏洞；Python 锁文件 45 个依赖的 pip-audit 报告零项已知漏洞。此结果只代表审计当时已收录的公告。
- Ubuntu Nginx 为 `1.24.0-2ubuntu7.19`，已包含 [USN-8955-1](https://ubuntu.com/security/notices/USN-8955-1) 所列修复，不能只依据主版本号判断存在该漏洞。
