## 一、业务规则

### 1. 账号 / 权限 / VIP / 管理员

- [x] 全站开放注册，**不需要邀请码**；邀请码仅用于升级 VIP
- [x] VIP 开通：个人中心输入有效邀请码 → 立即生效，**无需人工审核**（邀请码表：`invite_code`，一次性核销）
- [x] 邀请码由管理员在后台批量生成/导出
- [x] VIP 权限：完整网盘链接 + 提取码、全部自习室无限制、无需功能申请、**可填写自己的 AI API Key**
- [x] **VIP 可由管理员后台调整**：开通 / 续期 / 设有效期 / 降级撤销（每次操作留痕 + 通知用户）
- [x] 普通用户：链接脱敏、部分功能需申请
- [x] **功能申请流程**（已锁定）
  - 入口：个人中心 → 功能申请 → 下拉选择功能项 + 填写理由
  - 存储：`apply_record` 表（user_id / item_key / reason / status / audited_at / auditor_id / reject_reason）；**审批通过后写入 `user_feature_grant`，鉴权只读该表**（见 `03-DB` §3.1）
  - 状态枚举：`pending` / `approved` / `rejected` / `revoked`
  - **允许用户撤回**处于 `pending` 的申请
  - 后台：申请管理列表（申请人 / 项目 / 时间 / 理由）→ 通过 / 驳回（驳回必填原因）
  - **通知方式：站内消息 + QQ邮件，双通道（见决策 1）**
- [x] **管理员体系一期锁定**：单一固定主管理员（`role=admin`，邮箱写进 `.env` 的 `BOOTSTRAP_ADMIN_EMAIL`）
  - 不支持子管理员、不支持权限细分、不支持转让 → 二期
- [x] 管理员数据权限
  - 可查看：全部用户基础信息、全部申请记录、全部帖子、全部资料
  - **不可修改**他人的番茄记录 / 错题数据（只读）
  - **可删除**违规帖子、违规资料
  - **不可直接删除用户账号**（一期改为 `status=banned` 封禁，保留数据，便于事后追溯）
- [x] **一期开放渠道：仅 QQ邮箱 + 验证码登录**
  - 微信登录 / 手机号登录 / QQ 登录：**程序全部写完，Feature Flag 关闭，暂不开放**
  - 开关由后端 `GET /config` 下发，前端禁止用常量判断（见 `02-ARCH` ADR-014）
  - ⚠️ 微信开放平台 / QQ 互联需应用资质与备案域名；手机号登录需短信服务且合规风险高，开放前单独评估
  - 验证码：6 位数字，有效期 5 分钟，60 秒内不得重发，同一邮箱每日上限 20 次
- [x] **隐私模式**：见决策 2
- [x] 账号基础功能
  - 头像：上传七牛 `img.duzhi.xin`，可随时更换 / 恢复默认
  - 注销：一期提供「软删除」(`deleted_at`)，立即停用；番茄/错题/帖子数据在 T+30 天物理清理任务中删除 → 定时任务二期，一期只软删

### 2. 番茄钟（边界全部锁定）

- [x] **双计时模式：倒计时 + 正向计时（正计时）**；正向计时 `planned=0`，仍受 180min 上限保护
- [x] **自定义学习内容**（如"数学-线代"）→ 作为扇形统计的分组维度
- [x] 默认 25min 专注 / 5min 短休；可自定义专注、短休、长休时长
- [x] 长休息触发：连续完成 **4 个**番茄；**允许用户自定义**该数量（1–8）
- [x] **超时上限 180 分钟**：超过即自动 `quit(timeout)`
- [x] **数据取值：记录真实时长，封顶 180min**（见决策 3）
- [x] 暂停：支持多次，暂停时长累加从总时长扣除；**单次暂停上限 30min**，超时则该番茄自动 `quit`
- [x] **休息结束必须手动点「开始番茄」**，不自动循环
- [x] 状态枚举：落库只有 `done` / `quit`；`pausing` 仅为**客户端态**（前端计时器状态），不写库
- [x] **统计：日 / 周 / 月 / 年 扇形图**（按学习内容维度），**前端用 Dexie 本地数据实时计算**（秒级响应），同步完成后以后端返回的总量做校准
- [x] **年度热力图**：日历格子，按当日专注时长分 5 档着色（0 / <30min / <1h / <2h / ≥2h），可点某天看明细
- [x] 离线番茄：断网可开始/计时/完成，写 IndexedDB，联网入同步队列

### 8. AI 问答

- [x] AI 密钥模式：**方案 B —— 仅 VIP 用户可填自己的 Key**
  - 后端 AES-256-GCM 加密存储，主密钥在 `.env`（`AI_KEY_ENC_SECRET`），DB 泄露也拿不到明文
  - 前端**永不回显明文**，只返回掩码 `sk-...abcd`；修改时必须重新输入完整 Key
  - 前端不落 localStorage / Dexie，输入即提交
  - 服务端调用时解密 → 请求第三方 → 只回传模型回复；不回显 Key 相关错误详情
- [x] AI Key **不纳入离线同步**（敏感凭证，服务端单一权威）
- [x] AI 模型接入策略：**统一 OpenAI 兼容适配器 + 实时拉取模型列表**
  - 预设 5 家服务商：DeepSeek（默认）/ Kimi / 智谱 GLM / 硅基流动 / OpenAI + **自定义端点**（OneAPI、Ollama 等）
  - 模型名**不硬编码**：用用户 Key 调 `/v1/models` 实时拉取，缓存 24h；失败降级为手填
  - **流式输出**（StreamingResponse），超时 60s
  - 一期只做纯文本：不支持图片输入 / function calling / 联网搜索
  - 上下文：**最近 N 条按条数截断**（默认 N=10），一期不做 token 精确计算
  - 用量：**一期就记** `prompt_tokens / completion_tokens / latency_ms`（中期做面板不用补数据）
- [x] **AI 演进路线已定档**：P0 一期纯文本问答 → P1 中期（图片输入/token 精确截断/用量面板/会话管理/多 Key 容错）→ P2 后期（function calling/联网/Agent/自动批改）；架构预留 provider 适配层、ContextStrategy 可插拔、多 Key 唯一键（详见 `02-ARCH` ADR-012）
- [x] 对话历史：保存服务端；**不纳入离线同步**
