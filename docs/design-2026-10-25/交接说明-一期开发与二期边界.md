# 研时 · 交接说明（一期开发 + 二期草案边界）

> 给谁：接手开发的同学／外包。
> 一句话：**一期范围没变，照 PRD §6 做；文档里新出现的「社区/圈子」是二期草案，只看不写。**

---

## 一、你现在要做的（一期，范围未变）

- 依据：`01-PRD` §6 需求追踪矩阵（47 个功能点）+ `docs/prototype/prototype-v9.html` 61 屏。
- 自习室仍是：**用户自建房间 → 公开/私密 → 邀请码/邀请链接 → 房主审核入房**（F-20/F-21/UC-20）。
- 表：29 张，见 `03-DB` §3，不要自行加表。
- 已有预览实现里的「今日任务 / 科目管理 / 数据备份导出 / 我的梦校」**保留**，文档里暂时没写是因为文档落后于代码，我们会补，**不要当成多余功能删掉**。

## 二、你不用做的（二期草案，只看不写）

这三节是草案，**未评审、未排期**：

| 位置 | 内容 |
|---|---|
| `01-PRD` §8 | 大社区 → 圈子 → 房间三层，准入四档，共享四档 |
| `03-DB` §3.7 | `circle` / `circle_member` / `circle_join_request` 三张预留表 |
| `05-FLOW` §9 | 加入/审核/退出时序与状态机 |

**一期不要**：建 circle 表、给 `room` 加 `circle_id`、做探索页、把房间码迁到圈子。

## 三、但现在请这样写（零成本，省掉二期返工）

这四条不增加一期工作量，只是别把路堵死：

1. **房间一律带 id**：`/room/{id}/join`、`/room/{id}/heartbeat`、`/room/{id}/members`。文档本来就是这么写的；现有预览把 `/room` 写成无参单例，**这是要修回来的偏差**，不是二期才改。
2. **邀请码字段用 `room.invite_code`**，别用 `join_code`。入房申请的唯一索引别写 `uk(room_id, user_id, status)`——那会导致"被驳回两次后无法再申请"，用生成列 `pending_key`，见 `03-DB` §3.4。
3. **图片访问收敛到一个函数**，别处不许直接拼 `/attachments/view?key=` 或裸七牛 URL。二期要把"登录可读"换成"有权可读 + 短时效签名"，集中一处才换得动。
4. 遇到"谁能看谁的数据"，先分清是**准入**（能不能进）还是**授权**（给不给看）。二期整条线都建在这个区分上，一期的隐私模式就是授权侧的总开关。

## 四、判断有没有跑偏（验收自查）

出现以下任一情况，说明把二期做进一期了：

- 代码或接口里出现 `circle` / `/circles` / `explore`
- 底部 tab 从 6 个变 7 个（多了"社区"或"探索"）
- `room` 相关表或接口出现 `circle_id`
- 文档里 F-21 的"房间码"被改写成"圈子码"

## 五、如果确实要现在做二期

前置三件事必须先完成，否则做完要返工（详见 `01-PRD` §8.5）：

1. 附件权限升级：七牛私有空间 + `downloadToken`（或后端签发 ≤10 分钟临时 URL），不再"登录 + 拿到 key 就能看"；
2. 错题共享四件套：主动投入 · 查看日志 · 签名地址 · 撤回即失效；
3. 用户协议与免责声明更新（圈内传播、版权、截屏不可收回）。

## 六、你会追问的四个问题

**Q：文档里有两套房间规则（§6 和 §8），听哪个？**
一期听 `§6` + `03-DB` §3.4 + `05-FLOW` §5；`§8`/§3.7/§9 是二期。`01-PRD` §8.0 有一张「生效边界」表，写清了二期会改哪几条一期条款。

**Q：那我按 §8 先做，不是更省事吗？**
不行。§8 要改码的归属、房间的单例假设和附件权限，等于把自习室和同步一起改；而这三样一期都还没稳定。做完大概率推倒。

**Q：现有预览里的任务/科目/梦校，文档没有，删不删？**
不删。文档落后于代码，我们按实现补文档。以「现有功能保留 + 新功能按文档」为原则。

**Q：附件现在直接可读，要不要现在就改签名？**
不用。一期只需把访问收敛成一个函数；等圈子功能确认要做，再统一换成签名地址。

## 七、文档怎么用

- `docs/` 是唯一真源，`docs/site/` 全部由脚本生成，**不要手改站点 HTML**。
- 动手前先看 `docs/README.md` §七 修订记录（已到第四轮），那里记录了每轮改了什么、为什么。
- 本地校验：`cd _src/yan-shi && python tools/build_site.py --check`（口径 + 内链，非 0 退出）。
- 有疑问先看 `docs/prototype/gap-report.md`，三轮缺口核对都记在那儿。
