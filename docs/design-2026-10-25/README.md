### C. 被个人开发者最常忽略、但一定会踩的坑（重点）
| 坑 | 后果 | 对策（已写） |
|---|---|---|
| **时区混乱** | 番茄跨零点、"今日时长"统计错乱 | 全系统**统一 UTC 存储**，前端渲染转本地时区；`03-DB` 约定 + `05-FLOW` 番茄口径 |
| **客户端时钟漂移** | 用户改系统时间刷时长；离线计时与服务端对不上 | 服务端签发 `server_time`，客户端算 `clock_offset = server_time - client_time` 存内存，时长一律用 `Date.now() - offset` 推算；`04-SYNC` §6 |
| **同步重放导致数据重复** | 弱网重试 → 一条番茄变两条 | 每条 mutation 带 `op_id`，服务端 `sync_op_log` 幂等去重；`04-SYNC` §5 |
| **断点续传缺失** | 同步一半断网，下次全量重传 → 大量冲突 | 分批处理 + `push` 返回 per-op 结果，成功即出队；`04-SYNC` §4 |
| **SQLite → MySQL 字段差异** | SQLite 不校验类型，上线炸一片 | `03-DB` §4 迁移对照表 + 约束写一写在 ORM 层显式声明长度 |
| **XSS（v-html 渲染帖子）** | 开源站被植入脚本 | 统一用 Markdown 白名单渲染或纯文本 + 转义；`02-ARCH` §5 |
| **JWT 存储位置** | localStorage 存 token 被 XSS 盗用 | 一期：内存 + sessionStorage 承载 access_token，refresh_token 存 httpOnly Cookie（同域部署）；`02-ARCH` §5 |
| **图片上传伪造类型** | 改扩展名传 HTML → 存储型 XSS | magic bytes 校验 + 随机文件名 + 强制 `Content-Type`；`02-ARCH` §5 |
| **离线 sequence 顺序错乱** | 先改后删变成先删后改 → 数据复活 | outbox **严格 FIFO**，同一记录的操作不可并发提交；`04-SYNC` §3 |
| **验证码被刷** | QQ 邮箱 SMTP 日配额打满 / 被当垃圾 | IP + 邮箱双限流 + 图形验证兜底；`05-FLOW` §1 |
| **没有回滚方案** | 上线失败无法恢复 | Nginx 版本目录 + 一键回退指向上一版本；`10-OPS`（第 3 步） |
| **没有备份** | 数据库挂了全站数据清零 | 每日 mysqldump + 七牛异地 + 恢复演练；`10-OPS`（第 3 步） |

## 四、Definition of Done（完成的定义）

一个功能分支要合并进 `dev`，必须同时满足：

- [ ] 功能行为与 `01-PRD` 对应用例的**验收标准逐条对齐**
- [ ] 涉及的表已在 Alembic migration 中落 migration，非本地临时建表
- [ ] 接口已登记 `06-API`，含错误码、鉴权要求、幂等说明
- [ ] 写操作**全部走走谈 outbox / DAO 层**，没有绕过事务的原始 SQL
- [ ] 前端 UI 遵循 `07-UI` 的 Token（不用裸写颜色、时长数值）
- [ ] 覆盖了下面的最小测试：正常路径 + 1 个边界（尤其番茄超时/暂停/离线同步）
- [ ] `npm run build` 与 `python -m compileall` 均无错，`main` 分支可部署
- [ ] 日志无 DEBUG 残留，无 print，无硬编码密钥（跑一遍密钥扫描）
- [ ] commit message 符合规范，PR 描述写明验证方式

## 五、变更控制流程（防止开发中反复推翻）

| 变更类型 | 处理方式 |
|---|---|
| 调整 UI 文案、颜色、尺寸 | 直接改，无需记录 |
| 修改某个字段含义 / 加字段 | 必须先在 `03-DB.md` 改表设计 → 再改代码，并更新日期 |
| 修改业务边界（如番茄超时阈值从 180 改 120） | **回到 `checklist.md` 修改并标注日期**，同时更新 `01-PRD` 与 `04-SYNC` 受影响处 |
| 新增一期功能 | 默认**拒绝**。`11-RISK` 记录候选，进二期 backlog |
| 删减一期功能 | 可以，但必须在 `01-PRD` 的 MoSCoW 里从 Must 降级到 Won't，并说明原因 |

> 铁律：**先改文档，后改代码。** 任何越过文档直接写码的改动，合并时视为不合格。
