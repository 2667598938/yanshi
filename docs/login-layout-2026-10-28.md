# 登录页补全：电脑双栏与完整账号流程

日期：2026-10-28。基于 `cde4b28`。此前的电脑端改造保留了登录页的窄外壳，本次单独补齐；用户截图反映的是实际遗漏。

后续入口规则已由[登录准入与品牌开场](brand-opening-and-admission-2026-10-28.md)补充：关闭注册隐藏注册入口，有效邀请码不绕过关闭状态；取消游客入口，所有业务页要求登录。以下174项测试为本轮较早快照，当前总数见开发状态。

## 页面改动

- 登录路由使用独立的全宽外壳，不再受全站旧 520px 限制；其他说明页不受影响。
- 有效视口至少 960px 时，左侧展示研时的任务/专注、错题/复习、AI 学习助教、小组/自习室和隐私边界；右侧使用最多 440px 的紧凑表单。
- 窄屏收起介绍区，显示小型品牌与登录表单。手机输入字号 16px，验证码行允许收缩；注册长表单使用页面自然滚动。
- 登录、注册、找回密码和已开放的手机号渠道使用同一套字段与提示样式；增加密码显示/隐藏、真实标签、可键盘操作的协议按钮。
- 第三方按钮仅展示服务端实际开启的渠道；关闭注册时不再把“自动注册”作为无条件按钮承诺。
- 登录页介绍已有功能，不增加虚构的在线人数、学习记录或额外权限。AI 仍需本人 Key，小组共享与个人隐私规则保持原合同。

## 同时修复的交互缺陷

1. 手机号流程原先要求同意协议，但该分支没有勾选入口，且错误/成功提示放在邮箱分支。本次将协议、提示和提交放到共用区域。
2. 找回密码原先显示确认密码但未比较两次输入；本次与注册一起校验，不一致时不调用重置接口。
3. 验证码请求等待响应时增加状态锁，失败后恢复重试；登录等待期间禁止重复提交和切换模式。
4. 密码登录时如果有已开放的第三方登录，仍保留对应同意入口，避免切换方式后无法授权。
5. 登录、手机验证与 OAuth 回调统一使用站内 redirect，继续返回原目标页面。

## 验证结果

前端全量 174 项、44 文件通过，生产构建成功。本次新增 10 项账号流程组件用例、10 项登录布局用例。后端业务与数据库未修改。

布局测试加载真实 App、AuthView 和编译后的 scoped 样式，检查父外壳与媒体规则，覆盖电脑有效宽度 1024/1093/1366/1440/1920 和窄屏 320/360/390/430/768。其中 1093px 用于覆盖常见电脑 125% 缩放后的有效宽度；这不等于真实浏览器缩放验收。

本地预览 /login、新 AuthView 模块与响应式样式请求均 HTTP 200。Tabbit 稳定启动器仍未建立有效连接，未取得实时浏览器截图；像素布局、真实缩放、软键盘和触控待实机核验。happy-dom 在动态 resize 后存在计算样式缓存，因此尺寸测试使用独立页面实例，不以该环境证明真实拖动窗口。

## 快速检查

1. 电脑打开 /login，确认品牌介绍与表单并排，表单不再是整页大卡片；窄屏应只显示紧凑表单。
2. 切换邮箱验证码和账号密码，检查显示密码、忘记密码、协议弹窗及错误信息。
3. 注册或找回密码时故意输入两次不同密码，应拦截并提示；改成一致后才能请求。
4. 管理员实际启用手机号/第三方服务后，确认对应入口可见，协议能勾选，错误提示在当前表单内可见。未配置服务不作为真实联调通过。
