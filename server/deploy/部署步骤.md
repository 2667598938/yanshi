# 研时部署与恢复

> 本文是systemd备选。当前Azure Ubuntu24.04、宿主Nginx/Certbot环境优先使用[Compose部署手册](../../deploy/azure/README.md)。不要混用两个启动器或数据库写入进程。

当前代码仓库为单仓：后端在`server/`，前端在`web/`。下列示例按Linux单机部署编写。实际域名、证书和第三方服务需使用自己的配置；此文不会自动启动或对外开放服务。若当前仍处于备案审核阶段，继续遵循已有的停机安排。

## 1. 目录和运行身份

将已验收版本检出到`/opt/yanshi`。创建普通系统用户`yanshi`，授予`/opt/yanshi`读取权限，`/var/lib/yanshi`写入权限。前端静态文件还需允许Nginx读取。配置放`/etc/yanshi/server.env`，权限`640`，所有者`root:yanshi`；密钥不要进入仓库。

```bash
cd /opt/yanshi/server
python3 -m venv .venv
.venv/bin/pip install --require-hashes -r requirements.lock
cd /opt/yanshi/web
npm ci
npm test
npm run build
```

## 2. 生产配置

参照`server/.env.example`填写环境文件。至少配置：

```ini
ENVIRONMENT=production
DATABASE_URL=sqlite:////var/lib/yanshi/prod.sqlite
IMAGE_DIRECTORY=/var/lib/yanshi/uploads
MAIL_DIRECTORY=/var/lib/yanshi/mail
JWT_SECRET=<独立生成的足够长随机值>
AI_KEY_ENC_SECRET=<独立生成的足够长随机值>
PUBLIC_ORIGIN=https://example.com
CORS_ORIGINS=https://example.com
MAIL_CONSOLE=false
REGISTRATION_OPEN=false
ACCOUNT_MAX_USERS=4
FEATURES=checkin_room,resource,post,inspiration,dream_school
AUTH_CHANNELS=email
IMAGE_STORAGE=qiniu
```

SMTP填写真实发信账号与授权码。七牛必须是私有bucket，填写AK/SK/bucket/地域；本项目生产环境拒绝用本地存储上传图片。`QINIU_DOMAIN`不是S3访问的必要配置，不要为了测试改成公开bucket。

首次seed默认关闭注册；已有库的注册开关保留原值，部署后检查后台配置。扩大使用人数时修改`ACCOUNT_MAX_USERS`，0表示无人数上限；房间四人席位与账号名额互不绑定。即使取消人数上限，也应按服务器资源逐步开放。

## 3. 迁移、初始化与启动

在加载同一份生产环境变量后运行：

```bash
cd /opt/yanshi/server
.venv/bin/alembic upgrade head
.venv/bin/python -m app.seed --quiet
```

`ADMIN_PASSWORD`在首次初始化时设置，避免依赖随机密码输出；以后seed不会覆盖已有账号。安装`server/deploy/yanshi.service`到systemd，并按实际路径校对。该服务使用普通用户、单worker、写目录限制和journald日志。

配置Nginx示例中的实际域名及证书前，先把`server/deploy/yanshi-security-headers.conf`安装到`/etc/nginx/snippets/yanshi-security-headers.conf`，用`nginx -t`验证再启用。HTTP跳转HTTPS；生产refresh cookie为Secure，不能用纯HTTP验收登录。SSE代理关闭缓冲。不要暴露8000端口。

```bash
systemctl daemon-reload
systemctl enable --now yanshi
curl --fail http://127.0.0.1:8000/health/ready
journalctl -u yanshi --since today
```

`/health`仅说明进程可达；`/health/ready`必须返回200，才表示数据库连接与迁移版本就绪。后台`GET /api/v1/admin/diagnostics`只返回配置是否完整、功能开关和配额，不返回密钥。四人SQLite继续使用单worker；扩大到多worker前使用MySQL并做并发验收。

## 4. 第三方渠道与关闭的房间类型

微信/QQ需要真实平台AppID/Secret以及登记好的HTTPS回调：`/api/v1/auth/oauth/{wechat|qq}/callback`。OAuth要求一次性state和同一浏览器cookie。仅在配置完成、真实账号联调通过后将渠道加入`AUTH_CHANNELS`。

手机号登录与绑定使用腾讯云短信，配置`SMS_PROVIDER=tencent`及SecretId/SecretKey/SdkAppId/签名/模板ID。模板仅有一个验证码变量；如现有模板带两个变量应另建匹配模板，不能直接套用。真实签名、模板、余额和送达由服务商配置决定；自动测试不发送真实短信。[SendSms官方接口](https://cloud.tencent.com/document/api/382/55981)、[TC3签名说明](https://cloud.tencent.com/document/product/1124/100982)。生产未配短信时明确报错，不会伪报已发送。

`video_small_room`、`cloud_video_room`默认关闭；加入FEATURES后复用房间创建、邀请/审批、成员、心跳、踢人和解散流程，还要求VIP或room授权。依照PRD F-26，本范围不包含视频推流或摄像头监督；开启这些房间类型不代表具备音视频传输能力。

## 5. 备份、验证与恢复演练

加载生产环境配置后运行（产物敏感，应限制权限并复制到独立备份位置）：

```bash
cd /opt/yanshi/server
.venv/bin/python scripts/backup.py --output /var/lib/yanshi/backups --keep 14
.venv/bin/python scripts/restore.py /path/to/yanshi-backup-TIMESTAMP.zip
.venv/bin/python scripts/restore.py /path/to/yanshi-backup-TIMESTAMP.zip --target /var/lib/yanshi/restore-drill-NEW
```

备份包含SQLite一致性快照、SHA256文件清单和现有本地图片（包括切七牛后保留的旧本地附件）。不包含七牛远端对象：必须另外启用对象版本保留/独立备份，并演练对象恢复。MySQL使用原生一致性备份工具，本脚本不会冒充MySQL备份。

恢复仅允许尚不存在的新目录，会检查路径、文件哈希、SQLite完整性与外键；不会覆盖当前数据。恢复结果为`database.sqlite`与可选`uploads/`。先用隔离的数据库路径和端口启动验证，再在维护窗口停服务切换配置；不要边运行边覆盖原库。完整恢复还需要原`AI_KEY_ENC_SECRET`，否则旧BYOK密文无法解密；密钥应在仓库和普通备份包之外安全保存。

更新前备份、迁移、构建并检查ready。回滚优先回到上一版代码；若已发生不兼容数据迁移，应停写并恢复到新目录后切换，避免直接降级造成数据损失。邮件任务可能在SMTP已收取但进程尚未记账时重发，语义为至少一次；站内通知按去重键保持唯一。
